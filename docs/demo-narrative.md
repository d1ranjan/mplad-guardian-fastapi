# Five-Minute Demo Narrative

## 0:00–0:35 — Frame the outcome

“MPLAD Guardian helps a review team decide where to look first. It does not declare wrongdoing. It converts project-level financial, location, timeline, vendor, and progress data into evidence-backed review priorities.”

Open **Command centre**. Point to the completed audit-run code and the dashboard’s open-priority, critical-case, and sanctioned-value indicators. Emphasise that the workspace is an explicitly synthetic, reproducible demonstration.

## 0:35–1:25 — Explain the risk portfolio

Use the detector chart and its labels. Explain that each detector is independent and reviewable: peer-cost variance, potential duplicate work, vendor concentration, stalled delivery, and source-record quality. Use the dashboard signal filter to narrow the visible priority queue, then select **View full queue**.

## 1:25–2:35 — Investigate one case

Open the stalled-project case for **MPL-AS-302**. Read the case summary: days overdue, reported progress, and age of update. Then point to the detector-evidence table, showing observed values next to review thresholds. Show the analysis-run code and algorithm version, project source record, and financial milestones.

State: “Every number an analyst sees is preserved with the case. This makes the alert traceable and suitable for review—not an unexplained score.”

## 2:35–3:30 — Demonstrate other evidence types

Return to the queue and open the cost-outlier case **MPL-OD-105** to show actual cost, comparable peer median, deviation, and peer count. Then open **MPL-MH-202** to show the potential-duplicate text, locality/distance, date-gap evidence, and linked project. Finally, show **MPL-AS-301** for vendor share and HHI concentration context.

## 3:30–4:20 — Human decision point

Return to any open case. Use **Mark for field verification** and enter a short evidence-based note, such as “Request site photograph, completion record, and latest measurement-book entry.” Explain that another reviewer can later see the timestamped disposition in Review history. The alternative actions are resolve and dismiss with a retained note.

## 4:20–5:00 — Data onboarding and close

Open **Data import**. Download the CSV template, explain local preview and validation, and point out that blocking errors are separated from non-blocking quality warnings. Close with: “The original source CSV, checksum, import result, audit run, detector evidence, and reviewer actions form a connected chain of provenance.”

> **Closing message:** “This platform turns a large project register into a defensible review workflow: transparent signals, preserved evidence, and accountable human action.”
